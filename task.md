# SpatialTouch - Remaining Tasks

Based on the Development Roadmap in the project's README and the current state of the codebase, here are the detailed tasks left to be done:

## Phase 1: Foundation (v0.1) — done
- `[x]` **Complete Android Foreground Service**: `GestureService.kt` runs `START_STICKY`, owns the full pipeline lifecycle, and now checks `CAMERA` permission + guards `startForeground()` before starting (was previously reachable via a `SecurityException` crash path on Android 14+ if the toggle was hit without camera permission granted); `onDestroy()` guards each lateinit component so the new early-exit path can't crash on teardown either.
- `[x]` **Accessibility Service Implementation**: `SpatialTouchAccessibilityService.kt` injects scroll/tap/swipe via `GestureDescription` and system actions (back/home/recents/screenshot) via `performGlobalAction`. `MainActivity`'s `performAction` handler now reports `ACCESSIBILITY_NOT_ENABLED` instead of silently no-opping when the service isn't connected.
- `[x]` **MethodChannel Bridge**: `gesture_channel.dart` wraps all four channels (`gestures`, `gesture_events`, `camera_frames`, `volume`). `startService` now surfaces `PERMISSION_DENIED` as a `PlatformException` instead of the service dying invisibly; `home_screen.dart`'s toggle and `ActiveHoursScheduler`'s poll loop both catch it and recover gracefully. `ActionDispatcher`'s gesture→action map was switched to `ConcurrentHashMap` to fix a real read/write race (writes on the main thread from profile switches, reads from MediaPipe's background result-listener thread on every gesture).

## Phase 2: Vision Core (v0.2) — done
- `[x]` **MediaPipe Integration**: `HandTracker.kt` runs the real MediaPipe `HandLandmarker` in `LIVE_STREAM` mode (GPU delegate, falls back to CPU), extracting all 21 landmarks + handedness confidence per frame.
- `[x]` **Gesture Detection**: `GestureInterpreter.kt` detects all 13 gestures (not just wave up/down) from real landmark geometry. Fixed a real bug where the cooldown gate short-circuited *before* the wrist-history update, freezing `wristHistory` for the whole cooldown window (300–2000ms); the first post-cooldown frame then measured its delta against a stale pre-cooldown frame, which could spuriously fire a wave gesture immediately after almost every real one. Cooldown now only gates firing, not history bookkeeping. Also fixed `isThumbsDown` only checking 2 of 4 fingers curled (asymmetric with `isThumbsUp`), now checks all 4.
- `[x]` **Confidence Gate**: Implemented and enforced first in `interpret()`. `cooldownMs`/`minConfidence`/`motionThreshold` are now `@Volatile` — they're written from the main thread (calibration/performance-mode changes) but read from MediaPipe's background result-listener thread on every frame, and without the annotation a setting change wasn't guaranteed to become visible promptly.

## Phase 3: Background Engine (v0.3) — done
- `[x]` **Background Camera Processing**: `BackgroundCameraManager.kt` runs CameraX `ImageAnalysis` headlessly via a manual `LifecycleOwner`. Fixed `stop()` blocking whatever thread calls it (a real ANR risk — it's invoked from `SmartWakeManager`'s sensor callback on the main thread) with a synchronous `ProcessCameraProvider` `.get()`; now mirrors `start()`'s async `addListener` pattern. Also wrapped the frame analyzer body in try/catch/finally: previously an exception during JPEG compression/decode (OOM at 30fps, a buffer closed concurrently) would crash the whole app (Android kills the process for an uncaught exception on any thread) and `imageProxy.close()` would never run, stalling `STRATEGY_KEEP_ONLY_LATEST` backpressure.
- `[x]` **Smart Wake Filter**: `SmartWakeManager.kt` gates the camera on proximity NEAR + accelerometer stability, with a no-proximity-sensor fallback to always-on. No code changes needed — the design already correctly delegates the "SmartWake disabled for testing" bypass to `GestureService`, not this file.
- `[x]` **Floating Overlay**: `OverlayManager.kt`'s dynamic-island overlay already guarded `removeView()`/`updateViewLayout()` against detached views; `buildOverlay()`'s `windowManager.addView()` — the more failure-prone call — had no equivalent guard (e.g. `SYSTEM_ALERT_WINDOW` revoked between `show()`'s permission check and this call). Added a matching try/catch.

Known follow-up (not fixed, needs a device to validate): rapid SmartWake wake/sleep flapping could race `start()`/`stop()` against each other since `stop()`'s work is now deferred by a frame via `addListener` — a full fix needs all camera control funneled through a single serial command queue, which is a bigger change than a hardening pass without a device to test on.

## Phase 4: Full Customization (v0.4) — done
- `[x]` **Gesture-to-Action Mapping Engine**: `ActionDispatcher.kt` executes the right system action per gesture. **Found a major gap while hardening**: `ProfileEditorScreen` (the actual per-app UI) used invented gesture names (`"Double Tap Air"`, `"Circular Motion"`) that don't exist in `GestureInterpreter`, a separate human-label action vocabulary that didn't match `ActionDispatcher`'s real `actionId`s, saved everything to ad-hoc `SharedPreferences` keys, and never called `GestureChannel.loadProfiles()` — so editing a profile in the app had **zero effect** on native gesture behavior. Rebuilt the screen to use the real 13 gesture keys and real 14 `actionId`s, read/write through `ProfileDatabase`, and call `syncToNative()` on save.
- `[x]` **App Profiles Database**: `ProfileDatabase` (sqflite) existed but was never imported anywhere outside its own file — fully dead code. Now wired into `ProfileEditorScreen`, and a new `ProfileDatabase.syncToNative()` pushes the full profile set to `GestureChannel.loadProfiles()` — called on save, on app startup (`main.dart`), and right after the service starts (`home_screen.dart`), since the native cache is empty until pushed. Also fixed two real DB bugs found in the process: `insertProfile()` used `ConflictAlgorithm.replace` keyed on `package_name`, which deletes-and-reinserts under a *new* autoincrement id on conflict — since sqflite doesn't enforce foreign keys by default, the old profile's `gesture_mappings` rows were permanently orphaned every time an existing profile was re-saved (fixed: look up the existing row and update in place); and `gesture_mappings` had no unique constraint on `(profile_id, gesture_key)`, so `upsertMapping()` could create duplicate rows instead of replacing (fixed by adding the constraint).
- `[x]` **Foreground App Matcher**: `ForegroundAppMatcher.kt` polls `UsageStatsManager` every 1.5s and was already correctly implemented — no changes needed. It only becomes meaningful now that profiles actually reach the native cache.

## Phase 5: Polish & UX (v0.5) — done
- `[x]` **Onboarding & Calibration Wizard**: Found two more instances of the same "UI claims something happened, nothing actually did" pattern as v0.4:
  - The onboarding Calibration step's "Calibration Complete" button just ran a 2.2s fake delay and marked itself done — it never called `CalibrationService`, never touched `GestureChannel.setCalibration()`, and the real camera-driven calibration wizard (`CalibrationScreen`, reachable from Settings) was never invoked. So a fresh install's onboarding never actually calibrated anything, despite the page's own copy promising to "measure lighting and distance thresholds." Fixed: this step now pushes the real `CalibrationScreen` and only advances if it reports back a real completed save.
  - The Accessibility Service step marked itself "granted" the instant you tapped "Open Accessibility Settings" — *before* you'd done anything in the Settings app, since Dart had no way to check the real state. Added a native `isAccessibilityServiceEnabled` check (`SpatialTouchAccessibilityService.instance != null`, already tracked natively, just never exposed) and a `WidgetsBindingObserver` that re-verifies the real state whenever the onboarding screen regains focus, so the checkmark only appears once it's actually true.
- `[x]` **Active Hours Scheduling**: `ActiveHoursScheduler` already implemented and hardened during the v0.1 pass (error propagation fix).
- `[x]` **Performance Modes**: `PerformanceModeService` (3 presets, FPS/cooldown) reviewed — no issues found, already correct.
- `[x]` **Haptic Feedback**: `HapticService.kt` reviewed — already correctly guards by API level and wraps every call in try/catch, no issues found.
